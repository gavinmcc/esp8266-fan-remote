Remaining Diagnostic Actions
1
Confirm MDMCFG2=0x30 via startup log
Flash, open Serial Monitor, look for: MDMCFG2=0x30 (expect 0x30). If it shows 0x20, the 0x30 fix was not compiled in. The last test log was truncated and this cannot be confirmed.
2
Verify OOK PA gating with /carrier_ook
Add endpoint that sends alternating 0xFF/0x00 blocks (half-on, half-off carrier). In true OOK mode the physical remote should work through the intermittent carrier. If the remote gets jammed just as strongly as with all-0xFF, the PA is not gating (OOK broken despite 0x30). This is the key test to verify modulation — not just RF emission.
3
Increase REPS from 8 → 15
Physical remote captures show ~12 repetitions per button press. Our firmware sends 8. Some receivers require a minimum run of consecutive valid frames before accepting a command. This is a free change: bump #define REPS 15.
4
Add /dumpregs to read back all CC1101 registers
Read MDMCFG2, MDMCFG1, MDMCFG4, MDMCFG3, FREND0, PKTCTRL0, PKTCTRL1, FSCTRL1, FSCTRL0, FREQ2/1/0, MCSM0/1, CHANNR and print them all. Compare against the CC1101 datasheet expected values for OOK at 303.92 MHz. Eliminates all register ambiguity in one shot.
5
Self-capture: transmit while capture sketch listens
Flash capture.ino on the same (or second) ESP8266, place it near the fan_remote ESP8266, trigger a command, and see if the capture sketch decodes the correct pulse pattern. This verifies the actual OOK signal being emitted. Requires two ESP8266+CC1101 pairs, or brief firmware swap.
